### 工具链说明

本项目上游用 **uv** 管理依赖（`uv.lock`、`[tool.uv.workspace]`、`Makefile` 里 70+ 处 `uv run`）。
但 uv.exe 在受 IPGuard 管控的机器上会踩到加解密边界（见文末），所以本地开发改用：

| 职责            | 工具                         |
| --------------- | ---------------------------- |
| Python 版本管理 | **pyenv**（pyenv-win） |
| 环境隔离        | **venv**（标准库）     |
| 包安装          | **pip**                |

> 注意：`uv.lock` 仍然是上游的唯一锁文件，pip 这条路**不读** `uv.lock`，依赖版本由 pip 自己解析 +
> `scripts/pip-constraints.txt` 收窄。所以本地装出来的版本组合和 CI 不保证逐位一致；
> 提交 PR 前如需完全对齐 CI，仍要用 uv 验证一次。

### 首次安装

进入项目根目录：

```bash
# 后端环境（pyenv + venv + pip）一键搭好，并自动从 .env.example 生成 .env
bash scripts/pip-setup.sh

# 前端依赖（等价于 make install_frontend）
cd src/frontend && npm install
```

`scripts/pip-setup.sh` 做的事：

1. 用 pyenv 确认/安装 Python 3.13.1，并写入 `.python-version`（该文件已被 `.gitignore` 忽略）。
2. 用该解释器创建 `.venv`。
3. 升级 `pip` 到 **>= 25.1** —— 低版本没有 `--group`，装不了 `[dependency-groups]` 里的 dev 依赖。
4. 预装 `hatchling==1.31.0` 把 wheel 灌进 pip 缓存（工作区 18+ 个包都用它构建，否则每个包的
   构建隔离环境都要重新下一遍）。
5. **一次 pip install** 把所有本地工作区包以 editable 装进去 —— 这一步替代
   `[tool.uv.sources]` 的 `workspace = true`。必须放在同一条命令里，pip 的解析器才会用本地源码去满足
   `langflow-base~=1.13.0` / `lfx-*` 这些声明；分开装的话 pip 会去 PyPI 下已发布的 wheel，
   改本地代码就不生效了。
6. `pip install --group dev` 装测试/lint 依赖。

常用环境变量：

```bash
PY_VERSION=3.11.3 bash scripts/pip-setup.sh          # 换 Python 版本
WITH_OPTIONAL_BUNDLES=1 bash scripts/pip-setup.sh    # 追加 [bundles] extra 里的可选 bundle
SKIP_DEV=1 bash scripts/pip-setup.sh                 # 不装 dev 依赖组
BASE_EXTRAS=postgresql,pgvector bash scripts/pip-setup.sh   # 改 langflow-base 的 extra
```

重建环境：删掉 `.venv` 再跑一次脚本即可。

#### pip 相比 uv 的两个落差

* **没有 `--frozen`。** `uv sync --frozen` 严格按 `uv.lock` 装；pip 每次都重新解析。
* **`override-dependencies` 无法等价表达。** `pyproject.toml` 的 `[tool.uv] override-dependencies`
  是「强制改写」，pip 的 constraint 只能「收窄候选版本」，和上游声明冲突时 pip 直接报错而不是覆盖。
  能翻译的部分已放进 `scripts/pip-constraints.txt`，**改了 pyproject 里那一段记得同步这个文件**。

### 日常开发调试

先激活环境（每个新终端都要）：

```bash
source .venv/Scripts/activate     # Windows (Git Bash)
source .venv/bin/activate         # Linux / macOS
```

激活后，上游文档里所有命令去掉 `uv run` 前缀直接跑。

1、后端启动

```bash
# 项目根目录
uvicorn --factory langflow.main:create_app --host 0.0.0.0 --port 7860 --reload --env-file .env --loop asyncio
```

验证：启动后，浏览器访问 http://localhost:7860/health 返回 `{"status": "ok"}`

2、前端启动

```bash
# 项目根目录
cd src/frontend
npm start
```

验证：浏览器访问 http://localhost:3000

3、测试与格式化

```bash
pytest src/backend/tests/unit/xxx_test.py      # 单文件
pytest -n auto -m "not api_key_required"       # 后端单测
ruff format . && ruff check --fix .            # 格式化 + lint 自动修
```

> `Makefile` 里的目标（`make backend` / `make unit_tests` / `make format_backend` …）内部写死了
> `uv run`，在这条工具链下**不要用**，按上面的裸命令跑。

### VS Code 断点调试

`.vscode/launch.json` 已配置。

* **第一步**：让 VS Code 选中 venv 的解释器 —— `Ctrl+Shift+P` → `Python: Select Interpreter` →
  `./.venv/Scripts/python.exe`。选错解释器断点挂不上，这是换工具链后最容易踩的坑。
* **Debug Backend**（[launch.json:5-37](../.vscode/launch.json#L5-L37)）：`module: uvicorn`，带
  `justMyCode: false`，可以直接在 Python 代码里打断点。它用 `envFile: ${workspaceFolder}/.env`，
  所以 `.env` 必须存在（`scripts/pip-setup.sh` 会自动生成）。
  > 原先这里有一个 `"preLaunchTask": "Install Backend"`（指向 `make install_backend`，内部是
  > `uv sync`），在这条工具链下会报错。该行已从 launch.json 移除，依赖统一由
  > `scripts/pip-setup.sh` 安装。
  >
* **Debug Frontend**（[launch.json:69-75](../.vscode/launch.json#L69-L75)）：Chrome 附加到 3000 端口，
  前端 `npm start` 跑起来后再启动它，就能在 `.tsx` 里打断点。
* **Python: Debug Tests**：单测断点调试，直接用。

### IPGuard 加密问题（为什么弃用 uv）

uv.exe 创建 .txt，写 .txt 文件的是 python.exe（受控，写入自动加密），读文件的是 uv.exe
（不受控，读到的是密文）。问题出在**跨进程的加解密边界**上。

python 自己写自己读是正常的（写加密、读解密），只有 uv 调用 hatchling 这种
「Python 写 → uv 读」的场景才会炸。

两条解法，任选其一：

* **换成 pyenv + venv + pip（本文档的方案）**：写入和读取都由 `.venv/Scripts/python.exe` 完成，
  不跨进程边界，不需要申请白名单。
* **继续用 uv**：找 IPGuard 管理员把 `uv.exe`、`uvw.exe`、`uvx.exe` 加入白名单。
